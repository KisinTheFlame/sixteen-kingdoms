# 初步实现方向

## 第一阶段：数据先行

先用可审阅表格定义开局政权、人物、省份、外交和战争，再由脚本生成 EU4 历史文件。每一行数据都应保留史料依据、可信度和设计备注。

地图按区域全转换实施：中国及有直接联系的有限周边构成完整游戏世界，不在原版全球地图上局部覆盖。一般以州对应 `superregion`、郡对应 `area`、县对应省份；特别小的县只能逐案决定是否合并。静态层级以约 384 年行政区划为基准。先冻结世界边界、投影、画布和顶层分区，再选择一个核心区域细化到县，验证尺度、移动、战争、性能和界面表现后推广到全图。

## 第二阶段：最小垂直切片

选择一个年代与地区，实现：

- 完整的国家和省份历史；
- 可理解的开局外交与军事态势；
- 一套能够驱动分裂、联盟或整合的地区机制；
- 数个具有不同目标的可玩政权；
- 至少一次长期 AI 观察和人工冒烟测试。

事件、灾难和通用机制负责表现史实压力；任务树负责展示玩家可以主动建立的解决方案。任务奖励同时考虑即时恢复、制度路线与叙事承认，但不以永久通用数值代替新玩法。

## 第三阶段：系统化扩展

垂直切片稳定后，再扩展区域内容与通用系统。候选系统包括人口迁徙、军事集团、正统与官号、都城、门阀—州镇关系、部落整合和政权崩解。首轮专属历史与风味内容做到 439 年左右；玩家可以继续战役，后续南北朝扩展另行立项。

## 工程约定

- `docs/data/` 保存权威输入，生成文件不得成为唯一资料来源。
- 生成脚本应可重复运行，并在覆盖文件前检查目标范围。
- 本地原版游戏目录通过 `vanilla/` 链接访问，不进入 Git。
- 每次提交前运行本地化生成和静态校验。
